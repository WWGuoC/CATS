# Query-Plan-Aware Segment Migration on CXL Memory

Research artifacts for **Query-Plan-Aware Runtime Segment Migration for
In-Memory Databases on CXL Heterogeneous Memory**.

This repository contains the Hyrise implementation, retained experiment
scripts and configurations, result summaries, and paper plotting scripts.

## Repository Layout

| Directory | Contents |
| --- | --- |
| `hyrise/` | Database source, migration plugins, benchmark integration, and supplied third-party dependencies |
| `experiments/` | Experiment scripts, configurations, calibration tables, static-column profiles, and retained results |
| `figures/` | Paper figures in PDF format |
| `reproduce_figures.py` | Entry point for regenerating Figures 4--9 |
| `requirements.txt` | Python plotting dependency |

## Reproduce the Figures

With Python 3.12, run from the repository root:

```sh
python -m pip install -r requirements.txt
python reproduce_figures.py
```

The generated PDFs are written to `figures/`. Figures 1--3 are supplied
diagrams. Figure generation uses the included measurements and does not need
CXL hardware or database datasets.

## Implementation

The main components are in `hyrise/src/`:

- `plugins/semantic_placement_plugin.cpp`: initialization, ranking, background migration, and staging copies.
- `plugins/plan_analyzer.cpp`: logical-plan analysis and segment profiling.
- `plugins/policy_mapper.hpp` and `.cpp`: segment selection and byte-budget handling.
- `plugins/weisgut_static_column_plugin.cpp`: Weisgut-style static column placement baseline.
- `lib/memory/linear_numa_memory_resource.cpp`: NUMA allocation and free-space reuse.
- `benchmark/join_order_benchmark.cpp` and `tpch_benchmark.cpp`: workload entry points.

## Build and Run the System

### Linux Prerequisites and Build

The benchmark executables run CATS inside Hyrise; no separate database server
is required. Migration experiments need Linux with DRAM and CXL memory exposed
as NUMA nodes. The recorded build uses Clang 17 and C++20.

Install CMake (at least 3.18), Clang 17, Make, Python 3, Git, numactl,
autoconf, and the development packages for NUMA, TBB, Readline, ncurses,
SQLite3, PostgreSQL/libpq, and Boost (at least 1.81, container and date_time).
On Debian/Ubuntu, these libraries are typically packaged as `libnuma-dev`,
`libtbb-dev`, `libreadline-dev`, `libncurses-dev`, `libsqlite3-dev`,
`libpq-dev`, `libboost-container-dev`, and `libboost-date-time-dev`.
Check the Boost version provided by your distribution.

Clone into a path without spaces, as required by the bundled jemalloc build:

```sh
git clone https://github.com/WWGuoC/CATS.git
cd CATS
cmake -S hyrise -B hyrise/build -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_C_COMPILER=clang-17 -DCMAKE_CXX_COMPILER=clang++-17 \
  -DENABLE_NUMA_SUPPORT=ON
cmake --build hyrise/build --target hyriseBenchmarkJoinOrder \
  hyriseBenchmarkTPCH hyriseSemanticPlacementPlugin \
  hyriseWeisgutStaticColumnPlugin --parallel 8
```

Check that CMake detects NUMA: the project disables NUMA support if libnuma
is missing. Executables are generated in `hyrise/build/`, and plugins in
`hyrise/build/lib/`.

### Working Directory and NUMA Nodes

Run all commands below from the Hyrise source directory so that relative
resource, dataset, and plugin paths resolve correctly:

```sh
cd hyrise
mkdir -p results
numactl --hardware
export CATS_DRAM_NODE=1
export CATS_CXL_NODE=2
```

Replace these example node IDs with your machine's topology. The DRAM node
should have CPUs; the CXL node is the memory node used for the slower tier.
The commands bind execution to the DRAM node and let the placement plugin
manage data across both tiers. Capacity options use GiB despite their
`_gb` suffix. They configure placement budgets, not a process-wide memory
limit; allow additional memory for loading, query execution, and staging.

### Prepare the Data

TPC-H data is generated by the included generator when the benchmark starts.
The paper uses `--scale 100`; a first executable check can use SF1 without
loading a migration plugin or requiring CXL:

```sh
build/hyriseBenchmarkTPCH --scale 1 --queries 1,6 \
  -m Shuffled --time 30 --warmup 0 -o results/tpch_smoke.json
```

For JOB, download the IMDB tables with the included helper:

```sh
python3 scripts/setup_imdb.py imdb_data
```

The download uses an external dataset host. Alternatively, place the 21
IMDB table CSV files and their matching `.csv.json` metadata files in
`imdb_data/`; the helper skips downloading when all files are present.
JOB queries are included in `third_party/join-order-benchmark/`.

### Run CATS on TPC-H

This example runs all 22 queries at SF100 with 10 clients, a 4.1 GiB DRAM
budget, and a migration period of 5 seconds:

```sh
numactl -N "$CATS_DRAM_NODE" build/hyriseBenchmarkTPCH \
  --scale 100 -m Shuffled --scheduler --cores 0 --clients 10 \
  --time 1200 --warmup 10 --schedule_seed 4001 \
  --plugins build/lib/libhyriseSemanticPlacementPlugin.so \
  --semantic --dram_first \
  --lmem_ids "$CATS_DRAM_NODE" --rmem_ids "$CATS_CXL_NODE" \
  --dram_capacity_gb 4.1 --cxl_capacity_gb 100 \
  --demote_pct 0.95 --daemon_period 5 \
  -o results/tpch_cats.json
```

The other recorded TPC-H DRAM budgets are 8.2 and 16.4 GiB. Set the CXL
capacity to fit your available memory. In Shuffled mode, `--time` is the
timed workload duration in seconds; data preparation and per-query warmup
take additional time.

### Run CATS on JOB

This example follows the retained JOB rerun configuration, using all 113
queries, a 3.47 GiB DRAM budget, and a migration period of 1 second:

```sh
numactl -N "$CATS_DRAM_NODE" build/hyriseBenchmarkJoinOrder \
  --table_path imdb_data --query_path third_party/join-order-benchmark \
  --queries all -m Shuffled --scheduler --cores 0 \
  --dont_cache_binary_tables --clients 10 \
  --time 600 --warmup 0 --schedule_seed 1001 \
  --plugins build/lib/libhyriseSemanticPlacementPlugin.so \
  --semantic --dram_first \
  --lmem_ids "$CATS_DRAM_NODE" --rmem_ids "$CATS_CXL_NODE" \
  --dram_capacity_gb 3.47 --cxl_capacity_gb 100 \
  --demote_pct 0.95 --daemon_period 1 \
  -o results/job_cats.json
```

### Run the Baselines

For pure DRAM and pure CXL TPC-H reference runs, omit the placement plugin
and bind allocations to one memory node. The CPU node stays the same:

```sh
numactl -N "$CATS_DRAM_NODE" -m "$CATS_DRAM_NODE" \
  build/hyriseBenchmarkTPCH --scale 100 -m Shuffled \
  --scheduler --cores 0 --clients 10 --time 1200 --warmup 10 \
  --schedule_seed 4001 -o results/tpch_dram_only.json

numactl -N "$CATS_DRAM_NODE" -m "$CATS_CXL_NODE" \
  build/hyriseBenchmarkTPCH --scale 100 -m Shuffled \
  --scheduler --cores 0 --clients 10 --time 1200 --warmup 10 \
  --schedule_seed 4001 -o results/tpch_cxl_only.json
```

These references require enough memory on the selected node for the full
workload and do not apply the mixed-tier DRAM budget.

For the Weisgut-style static column baseline, use its dedicated plugin and
the included workload profile:

```sh
numactl -N "$CATS_DRAM_NODE" build/hyriseBenchmarkTPCH \
  --scale 100 -m Shuffled --scheduler --cores 0 --clients 10 \
  --time 1200 --warmup 10 --schedule_seed 4001 \
  --plugins build/lib/libhyriseWeisgutStaticColumnPlugin.so \
  --weisgut_static_column \
  --column_profile_path ../experiments/07_weisgut_static_column/profiles/tpch/column_profile.csv \
  --lmem_ids "$CATS_DRAM_NODE" --rmem_ids "$CATS_CXL_NODE" \
  --dram_capacity_gb 4.1 --cxl_capacity_gb 100 \
  -o results/tpch_weisgut_static.json
```

For JOB, use the JOB executable and workload arguments shown above, the
`profiles/job/column_profile.csv` profile under the same experiment directory,
and a 3.47 GiB DRAM budget. Keep the static plugin and omit the semantic
plugin and its migration flags.

Optional variants of the CATS commands:

| Variant | Additional arguments |
| --- | --- |
| No plan awareness | `--ablate_d1` |
| No staging replicas | `--ablate_d3_replica` |
| Cost-C3 greedy baseline | `--cost_c3_greedy --c3_calibration ../experiments/02_phase_b2/calibration/calibration.csv` |

The supplied calibration is from the recorded machine; recalibrate for
hardware-specific comparisons. Do not combine Cost-C3 with `--ablate_d1`
or `--placement_wfreq`.

### Results and Experiment Configurations

The `-o` argument writes benchmark metrics to JSON. CATS also writes
`<stem>_semantic_placement.csv` and `<stem>_daemon_metrics.csv` beside it.
The static plugin writes placement maps, selected columns, and
`<stem>_overhead.csv`. Choose a new output stem for each run.

Use `build/hyriseBenchmarkTPCH --help` or
`build/hyriseBenchmarkJoinOrder --help` to inspect all options.
See [experiments/README.md](experiments/README.md) for retained experiment
inputs and results. The
[rerun campaign plan](experiments/08_weisgut_repair_rerun/campaign_plan.json)
contains the per-run commands, seeds, budgets, and repetitions; replace its
original absolute paths and NUMA IDs before reuse. Regenerating the paper
figures uses the retained measurements, as described above.

## Availability

This repository contains the currently available source snapshot and result
materials, including the root Hyrise CMake configuration, resource directory,
and dependency declarations. Full benchmark datasets and compiled binaries
are not included. The commands above were checked against the supplied source
and retained experiment configurations; a clean Linux build and new CXL
benchmark runs have not been performed during packaging.

The supplied dependency trees are checked in as ordinary files; the nested
`hyrise/.gitmodules` preserves their original upstream locations. The CMake
file also declares an unused `cpp-btree` interface target whose directory is
absent from this snapshot.

The original Hyrise license is in [hyrise/LICENSE](hyrise/LICENSE).
Third-party license files are retained in their respective directories.
